Fix an over-narrow design in decision-trace-v1 found by user review. The invariant is not 'output text is byte-identical to a static table entry'; it is 'the output is exactly one of the candidates the program offered the model'. The decision model only ranks or scores bounded choices. Two legitimate composition patterns exist and the schema must support both: (A) code picks a frame from a table and splices deterministically retrieved text into it (table + index + slots, already supported); (B) code builds the candidate list as fully-composed strings ('Tell me more.', 'Earlier you said you bought a new car.') and the model chooses among them, in which case the output is byte-identical to the selected label of that decision. Add a 'source' discriminator to output covering both, implement and test it in tdm-trace, and correct the overstated 'byte-identical to a table entry' wording in docs/plan.md and README.md to state the real invariant.

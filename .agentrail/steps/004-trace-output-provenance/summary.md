Fixed an over-narrow design in decision-trace-v1 caught by user review. The invariant is 'the output is exactly one of the candidates the program offered', not 'byte-identical to a static table entry'; the decision model only ranks bounded choices. Output is now a serde-tagged enum over source:choice (byte-identical to the selected label of the cited decision) and source:table (frame with recorded slots filled). The old schema could not express composed candidate sets at all, which was the real defect; I had mis-framed that limitation as a threat to the project's central claim, and the 003 commit message overstated it. TextNotInTable renamed TextNotOffered; UnknownDecision added; missing or mixed source discriminators rejected. Three new tests cover the composed pattern including a candidate that lost and a sentence never offered. Corrected the overstated wording in plan.md, README.md, CLAUDE.md, AGENTS.md, docs/README.md.
